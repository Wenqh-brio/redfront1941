## 2. 数据流（单一数据源原则）

```
data/*.json  ──build-data.mjs──▶  data/generated/*.csv  ──编辑器导入──▶  UDataTable (DT_*)
     │                                                                        │
     └──build-data.mjs──▶  prototype/js/data.generated.js（浏览器原型）        ▼
                                                                    RFDataTypes 结构体
                                                                            │
                            RFDataTableLoader（运行时读取 Content/RedFront/Data/*.json 覆盖）
                                                                            ▼
                        RFLoadoutSubsystem / RFSurvivalComponent / RFSupportSubsystem
```

- **JSON 是唯一真源**；CSV 与原型数据都是生成物，禁止手改
- 复合字段（`effect` / `objectives` / `enemy_composition`）在 CSV 中以 JSON 字符串存储，由 `RFDataTableLoader` 二次解析
- 好处：策划改 JSON → 跑一条命令 → 数据表、原型、文档全部同步（56 关总表就是这么生成的）

## 3. 关键系统实现要点

### 3.1 RFWeightComponent（负重）

```cpp
// 与 data/classes.json 的 load_bands 一一对应
Light      : ratio <= 0.60 → SpeedMult 1.08, StaminaDrain 0.80
Standard   : ratio <= 0.85 → SpeedMult 1.00, StaminaDrain 1.00
Heavy      : ratio <= 1.00 → SpeedMult 0.92, StaminaDrain 1.25
Overloaded : ratio >  1.00 → SpeedMult 0.78, StaminaDrain 1.70, bCanSprint = false
```

- 每件装备在 `FRFItemDef::WeightKg` 中计重；**水与弹药是变量重量**（`CurrentWaterLiters`、`RoundsRemaining`）
- 重量变化触发 `OnLoadBandChanged`，驱动移动组件参数、动画速率与 HUD

### 3.2 RFSurvivalComponent（生存）

- 五轴：Health / Stamina / Food / Water / Warmth（+ Bleeding、Fatigue 次状态）
- 消耗速率乘 `URFGameInstance` 提供的难度系数（`difficulty_scaling`）
- 归零走"退化 → 掉血"两段式，与文档 02 第 3 节一致
- API：`EatItem(FName ItemId)` / `DrinkItem` / `UseMedical` / `TickSurvival(float Dt)`

### 3.3 RFBallistics（弹道）

- 弹丸为实体 Actor/Projectile：飞行时间、重力可选（原型为直线）、线段×圆连续碰撞
- 命中后按 **`EFRHitFace`（Front/Side/Rear）** 计算等效装甲：`ArmorMm × (Front ? 1 : Side ? SideRearRatio : SideRearRatio × 0.7)`
- 未击穿 → 火花与跳弹音；击穿 → 伤害与"断带"概率
- 提供 `static float ComputeEquivalentArmor(const FRFVehicleDef&, EFRHitFace)`

### 3.4 RFSupportSubsystem（支援火力）

- 状态：`CommandPoints`、`CooldownMap`、`PendingQueue`、`bRadioDestroyed`
- 呼叫校验链：电台 → CP → 冷却 → 观察条件 → 危险距离警告
- 弹着：`RoundsLeft × Interval` 逐发结算，散布 = `SpreadBase × 精度系数`
- 敌方反制：无线电测向（≥老兵难度 25%）、Flak 拦截（空中支援）
- 与 `RFSquadCoordinator` 联动：敌方班长存活超时 → 呼叫敌方迫击炮

### 3.5 RFEnemyAIController（AI）

- 感知：`SpotRange = AwarenessM × TerrainSightMult × ExposureMult`，受 `VisibilityM` 限制
- 行为树状态：`Idle / Advance / Fire / Cover / Flee`；`Advance` 使用"掩护跃进"（无导航网格时用切线绕行）
- 压制：`Suppression` 累积 → 降低精度、触发 `Cover`
- 士气：`MoraleBreakChance`（民兵 35%）
- `RFSquadCoordinator`：火力基点（MG42）、两翼跃进、反冲击时机、呼叫支援

## 4. 2D 渲染设置（DefaultEngine.ini 要点）

| 设置 | 值 | 原因 |
|---|---|---|
| 渲染器 | Deferred + DX12 | Lumen/TSR 可选，材质与后处理空间充足 |
| 抗锯齿 | TSR（或 TAA） | 高清手绘精灵边缘干净 |
| 相机 | 正交（Orthographic） | 2D 平面无透视畸变，世界单位可当米用 |
| 碰撞 | 2D 平面：Z 轴锁定 + `Paper2D` 平面碰撞profile | 角色只在 XY 平面移动 |
| 纹理流送 | 池 ≥1200 MB | 2048 px 精灵图集 |
| 帧率 | 平滑关闭 / 可配置上限 | 格斗式手感不需固定帧 |

## 6. 性能与优化

| 项 | 目标 | 手段 |
|---|---|---|
| 帧率 | 1080p60 中端 / 1440p60 高端 | 精灵合批、图集、粒子池 |
| 实体上限 | 400（含载具/粒子系统） | AI LOD：200 u 外降频思考（10 Hz） |
| AI 思考频率 | 0.1 s（近）/ 0.5 s（远） | 避免每帧寻路与视线检测 |
| 视线检测 | 每帧限流（每单位 0.2 s 缓存） | 原型已验证 240 实体下无压力 |
| 加载 | <8 s（SSD） | 关卡分块 + 异步加载精灵图集 |

## 8. 联机（规划，非首期）

- 首期纯单机（简化同步与反作弊面）
- 后续 2-4 人合作：玩家为同一小队不同专长；生存/负重/弹药各自独立；支援火力共享 CP 池
- 架构预留：所有玩法逻辑在 `GameState/Component` 层，避免放进 `PlayerController`；随机数使用可复现种子（原型已是 seeded RNG）
